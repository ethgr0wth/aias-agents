# ShadowCare — Platform Specification

## Product Overview

ShadowCare is a clinician-controlled AI operating environment for mental health workflows. It is a real-time, multi-agent system where AI participates in patient interaction — but the clinician remains the ultimate decision-maker.

**This is not a chatbot. This is infrastructure for supervised AI-assisted care.**

Built on the same real-time infrastructure as DevNetwork (device fingerprint auth, WebSocket messaging, bot orchestration, ecosystem isolation, matchmaking), ShadowCare repurposes that foundation for healthcare delivery. The AI backend is powered by AiAssist.net.

**Deployment Model:** Self-hosted, single-tenant. Each deployment runs on the doctor's infrastructure as a fully isolated instance. A managed offering includes monthly service charges for maintenance and upkeep.

**Encryption:** Out of scope for initial build. Architecture is encryption-ready — each namespace can receive its own encryption key. Crypto specs to be integrated in a future phase.

## Core System Architecture

### 1. Shadow Mode (Human-in-the-Loop)

All AI outputs are reviewable, editable, and controllable. The clinician can:

- **Approve** — Send the AI's response as-is to the patient
- **Modify** — Edit the AI's response before delivery
- **Override** — Replace with a completely custom message
- **Pause** — Halt the AI interaction entirely

AI appears active to the patient, but the clinician is always in control of the outcome. The patient sees a seamless conversation — they don't know messages are being reviewed.

This ensures:
- Safety
- Accountability
- Regulatory viability

### 2. Multi-Agent Interaction Layer (The Puppet Layer)

The system supports multiple AI "nurse" personas running **simultaneously**. Each agent has:

- A distinct therapeutic tone
- A different communication strategy
- A unique behavioral model

When a patient sends a message, **all agents generate their suggested response at the same time**. The clinician sees every agent's approach side by side in real-time:

```
Patient: "I'm feeling a bit down today. It's been a rough couple of days."

┌─────────────────────────────────────────────────────────────────┐
│  AGENT SUGGESTIONS (simultaneous)                               │
│                                                                 │
│  Haven (Empathetic Companion)                                   │
│  "I hear you. It takes courage to share that. What's been      │
│   weighing on you the most?"                                    │
│  [Approve] [Edit] [Dismiss]                                     │
│                                                                 │
│  Kai (Mindfulness Guide)                                        │
│  "Let's pause and take a breath together. Sometimes naming     │
│   what we feel is the first step. Can you put it into words?"  │
│  [Approve] [Edit] [Dismiss]                                     │
│                                                                 │
│  Nova (CBT Strategist)                                          │
│  "I'm sorry to hear that. Can you walk me through what         │
│   happened? Sometimes when we look at the specific events,     │
│   we find they're more manageable than they feel."              │
│  [Approve] [Edit] [Dismiss]                                     │
│                                                                 │
│  [Blend Selected] [Write Custom]                                │
└─────────────────────────────────────────────────────────────────┘
```

The clinician can:
- **Select** one agent's response to send
- **Edit** any agent's suggestion before sending
- **Blend** — combine elements from multiple agent suggestions
- **Write custom** — ignore all suggestions and type their own
- **Swap agents mid-session** — bring in a different agent's style
- **Inject interventions** — insert custom therapeutic prompts

This creates a **controlled decision theater** where clinicians guide AI behavior without breaking conversational flow. The agents compete to provide the best approach — the doctor picks the winner.

**Purpose:** Expose how different approaches impact patient response. The clinician sees cause and effect in real-time.

### 3. Live Simulation Environment (Shadow Room)

A controlled sandbox where clinicians can:

- Simulate patient scenarios with AI-generated test patients
- Observe AI agent behavior under different conditions
- Test intervention strategies before using them with real patients
- Validate system safety

This functions as:
- **Onboarding** — New clinicians learn the system
- **Training** — Practice different therapeutic strategies
- **Calibration** — Tune agent behavior to the clinician's preferences
- **Trust-building** — See the system work before going live

### 4. Behavioral Observation & Signal Engine

The system continuously analyzes patient interactions in real-time:

**Inputs observed:**
- Emotional trajectory (mood over time)
- Response patterns (length, latency, vocabulary shifts)
- Engagement levels (active vs withdrawn)
- Sensitivity to tone/phrasing

**Outputs generated:**
- **Trigger detection** — What caused a change in patient state
- **Trust / defensiveness signals** — Is the patient opening up or closing off
- **Escalation indicators** — When a situation needs immediate clinician attention
- **Mood tracking** — "2 Days Down", "Mood drop", trend visualization

**Key principle:** We are not guessing outcomes — we are observing cause and effect in real-time. Which agent's approach worked? Which phrasing caused the patient to open up? The system tracks behavioral attribution.

### 5. AiAssist.net Backend

All AI agent responses are powered by AiAssist.net:

- Multiple agents hit AiAssist simultaneously with different persona prompts and strategies
- All responses stream back to the clinician's puppet layer at the same time
- Configurable LLM model per deployment (default: Moonshotai Kimi K2 Instruct)
- Each agent has its own system prompt defining therapeutic approach, tone, and boundaries
- Token limits and reply caps are configurable per deployment

```
Patient message
    │
    ├──→ AiAssist (Haven persona prompt)  ──→ Response A ──┐
    ├──→ AiAssist (Kai persona prompt)    ──→ Response B ──┤──→ Clinician Puppet Layer
    └──→ AiAssist (Nova persona prompt)   ──→ Response C ──┘
                                                              │
                                                         [Select / Edit / Blend]
                                                              │
                                                         Patient sees one message
```

## Architecture

### Factory Pattern

ShadowCare uses a factory provisioning system. Doctors interact with a professional administration dashboard to configure and deploy isolated patient environments.

```
Factory (Provisioning Engine)
  └── Deployment (Doctor's Namespace)
       ├── Shadow Room (simulation sandbox)
       ├── Session Room(s) (single by default, "Universe Mode" for multiple)
       │    ├── Patients (matched via customizable intake questionnaire)
       │    ├── AI Agents (doctor-scoped personas, strategies, conversation starters)
       │    └── Clinician Puppet Layer (observe, select, edit, approve, inject)
       └── Signal Engine (behavioral observation, mood tracking, escalation)
```

### Namespace Isolation

- Each doctor's deployment runs in its own Redis namespace (key prefix: `sc:{deployment_id}:`)
- Patients only see their doctor's environment — no cross-deployment visibility
- A doctor can spin up multiple deployments (e.g., separate programs for anxiety, grief, addiction)
- Architecture supports per-namespace encryption keys (future phase)

### Universe Mode

- **Off (default):** All patients land in a single therapy room. Simplified experience for small practices. One room, one focused therapeutic environment
- **On:** Multiple rooms/groups scoped by the doctor. Patients are matched to relevant rooms based on their intake questionnaire answers. Full ecosystem functionality enabled

## Session Room — Clinician-in-the-Loop Interface

### Patient View (Right Panel)

The patient sees a natural, seamless conversation:

- Chat interface with the active AI agent (appears as one consistent presence)
- Mood indicators and check-in prompts appear contextually
- Clean, calming UI with the deployment's accent colors
- No awareness that messages are being reviewed or that multiple agents exist
- Typing indicators appear while the clinician reviews suggestions

### Clinician View (Left Panel) — The Puppet Layer

The clinician operates as a silent orchestrator:

**Live Session Panel:**
- Active session indicator with patient name and session duration
- Real-time patient message stream

**Multi-Agent Suggestion Panel:**
- When the patient sends a message, ALL configured agents generate their response simultaneously via AiAssist.net
- Each agent's suggestion appears in its own card with the agent name, strategy label, and response
- Each card has: **[Approve]** **[Edit]** **[Dismiss]** buttons
- **[Blend Selected]** button — combine elements from multiple suggestions into one response
- **[Write Custom]** — ignore all suggestions, type a custom message
- Clinician can swap which agent the patient "sees" mid-session

**Shadow AI Analysis:**
- Real-time behavioral signals alongside the conversation
- Mood trajectory visualization ("2 Days Down", "Mood drop")
- Engagement level indicators
- Trigger detection — highlights what caused a change in patient state
- Trust / defensiveness signals
- Escalation alerts when immediate attention is needed

**Session Controls:**
- Pause interaction (typing indicator stays active for patient)
- Switch active agent persona
- Inject custom intervention prompts
- End session with summary

### WebSocket Flow

```
Patient sends message
    │
    ├──→ WebSocket to Clinician (immediate — clinician sees raw message)
    │
    ├──→ AiAssist.net (Agent 1 persona) ──→ Suggestion A ──┐
    ├──→ AiAssist.net (Agent 2 persona) ──→ Suggestion B ──┤──→ WebSocket to Clinician
    └──→ AiAssist.net (Agent 3 persona) ──→ Suggestion C ──┘    (all arrive simultaneously)
                                                                  │
                                                           Clinician reviews
                                                           [Approve / Edit / Blend / Custom]
                                                                  │
                                                           WebSocket to Patient
                                                           (single message delivered)
```

**Patient experiences:** AI responded thoughtfully
**Reality:** Clinician selected the best approach from competing AI strategies

## Shadow Room — Simulation Environment

A controlled sandbox where clinicians practice before going live:

- **Simulated patients** — AI-generated test patients with configurable profiles and scenarios
- **Agent testing** — See how different agents handle edge cases (suicidal ideation, crisis, resistance, testing boundaries)
- **Strategy validation** — Test new therapeutic approaches safely
- **System calibration** — Tune agent personas, adjust tone, refine conversation starters

This is the clinician's training ground, onboarding experience, and trust-building layer. They see the system work before a single real patient uses it.

## Behavioral Signal Engine

Continuous real-time analysis running alongside every session:

### Signals Tracked

| Signal | Description | Source |
|--------|-------------|--------|
| Mood trajectory | Emotional state over time (up/down/stable) | Message sentiment analysis |
| Response latency | How quickly patient responds | Timestamp deltas |
| Message length | Getting shorter (withdrawal) or longer (engagement) | Character count trends |
| Vocabulary shifts | Negative language increasing/decreasing | Lexical analysis |
| Engagement level | Active participation vs minimal responses | Pattern matching |
| Trust indicators | Opening up, sharing more detail | Disclosure analysis |
| Defensiveness | Short answers, topic avoidance, pushback | Behavioral patterns |
| Escalation flags | Crisis language, self-harm indicators | Keyword + context analysis |
| Trigger attribution | Which agent approach caused which patient response | Cause-effect mapping |

### Clinician Dashboard

- Real-time signal overlay on the session view
- Historical mood charts per patient
- Session-over-session comparison
- Agent effectiveness metrics (which strategies work best for this patient)
- Exportable reports for clinical documentation

- `PUT /api/sc/deployments/{id}` — Update deployment config
- `DELETE /api/sc/deployments/{id}` — Decommission
- `POST /api/sc/deployments/{id}/seed` — Seed/provision
- `GET /api/sc/deployments/{id}/status` — Health check

- `GET /api/sc/deployments/{id}/questionnaire` — Get intake form config

- `GET /api/sc/deployments/{id}/rooms` — List rooms

- `DELETE /api/sc/deployments/{id}/agents/{agent_id}` — Remove agent

### Matchmaking
- `GET /api/sc/deployments/{id}/matchmaking` — Get rules
- `PUT /api/sc/deployments/{id}/matchmaking` — Update rules

### Sessions
- `POST /api/sc/sessions` — Start a session
- `GET /api/sc/sessions/{id}` — Get session state

- `GET /api/sc/sessions/{id}/signals` — Real-time behavioral signals
- `GET /api/sc/patients/{id}/signals/history` — Historical signal data
- `GET /api/sc/patients/{id}/mood` — Mood trajectory

- `GET /api/sc/shadow/scenarios` — List available test scenarios
- `POST /api/sc/shadow/scenarios` — Create custom test scenario

## Data Model (Redis)

### Key Patterns

```
sc:deployments                              — SET of all deployment IDs
sc:{dep_id}:meta                            — JSON deployment metadata
sc:{dep_id}:questionnaire                   — JSON questionnaire config
sc:{dep_id}:matchmaking                     — JSON matchmaking rules
sc:{dep_id}:rooms                           — SET of room IDs
sc:{dep_id}:room:{room_id}                  — JSON room data
sc:{dep_id}:agents                          — SET of agent user IDs
sc:{dep_id}:agent:{agent_id}                — JSON agent config + persona
sc:{dep_id}:agent:starters:{agent_id}       — JSON conversation starters
sc:{dep_id}:patients                        — SET of patient user IDs
sc:{dep_id}:patient:{user_id}               — JSON patient profile
sc:{dep_id}:session:{session_id}            — JSON active session state
sc:{dep_id}:session:suggestions:{sess_id}   — LIST of pending agent suggestions
sc:{dep_id}:session:history:{sess_id}       — LIST of delivered messages
sc:{dep_id}:signals:{user_id}               — TIMESERIES behavioral signals
sc:{dep_id}:mood:{user_id}                  — LIST of mood data points
sc:{dep_id}:messages:{room_id}              — LIST of message IDs
sc:{dep_id}:message:{msg_id}                — JSON message data
```

### Namespace Isolation Guarantee

All ShadowCare operations MUST include the `{dep_id}` prefix. No cross-deployment data access is possible at the key level. This is the foundation for future encryption — each namespace can get its own encryption key.

## Technology Stack

- **Backend:** FastAPI (Python) — same infrastructure as DevNetwork
- **Frontend:** TypeScript, Tailwind CSS, Framer Motion
- **Real-time:** WebSockets (simultaneous multi-agent streaming)
- **Database:** Redis (namespaced key-value)
- **AI Backend:** AiAssist.net (AiAssist SDK, configurable models)
- **Auth:** Device Fingerprint + TOTP 2FA (same as DevNetwork)

## Deployment & Hosting

- **Self-hosted:** Single container on doctor's VPS/infrastructure
- **Managed offering:** Monthly service charge for maintenance, updates, monitoring

- **Portable:** Same codebase as DevNetwork, different configuration

## Strategic Position

ShadowCare does not attempt to replace clinicians. It augments clinical judgment by making interaction dynamics visible, testable, and controllable.

We are solving the core barrier to AI in healthcare: **Trust**.

By enabling clinicians to observe, test, control, and validate — we remove the leap of faith.
